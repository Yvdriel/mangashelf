## Global auth model

`src/proxy.ts` (`export const config.matcher = ["/((?!_next/static|_next/image|favicon.ico|favicon-|icon.svg|apple-touch-icon.png|android-chrome-|manifest.json|icons|sw.js|api/import/upload).*)"]`) is the Next.js 16 proxy file that runs on every request and:

1. If no session cookie and the request is not `/login` or `/setup` → redirect to `/setup` (when zero users in DB) or `/login`.
2. If a session cookie exists, validate via `auth.api.getSession`; if invalid, redirect to `/login`.
3. If a valid session lands on `/login` or `/setup`, redirect to `/`.
4. `/api/auth/*` is always allowed (fast-pathed before the redirect logic). `/api/import/upload` is matcher-excluded so streaming uploads bypass proxy DB reads.

Because of (1)/(2), **every route is effectively auth-required** even when the route handler does not call `getSession()` itself (notably `/manager`, `/manager/[id]`, `/downloads`). Many handlers ALSO call `getSession()` or `requireAdmin()` as a second layer; those are noted per row.

Auth helpers:
- `getSession()` — returns the session or `null` (from `src/lib/auth-helpers.ts`).
- `requireAdmin()` — returns the session only when `session.user.role === "admin"`, else `null`. Used by admin-only handlers (returns 403 on failure).
